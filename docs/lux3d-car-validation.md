# Aholo Lux3D 车辆升级验收

日期：2026-09-13。本轮只修改本地游戏，未向 GitHub Pages 发布。

## 来源

整车为 Aholo Lux3D G1 任务 3431485，输入为自行生成、前牌文字为 VZ-0606 的单车参考图；输入提示词及使用方式见 `art/references/lux-gt-reference-generation.md`。原始 GLB 为 10,028,080 字节，SHA256 为 `5f79f1606c7773e7947c5dc02e84c6d7f72ce7b2153c54fe1eaf844e672a5838`。源模型、原始结果及检查数据保存在 `art/lux3d/car-plated-source*`。座椅为 Aholo Lux3D G1 任务 3430884。

Blender 5.2.1 LTS 实际导入并处理这些生成资产。整车处理脚本为 `tools/prepare-lux-car.py`，座椅处理脚本为 `tools/prepare-lux-seat.py`。运行时加载 `public/models/solstice-lux-gt.glb` 及 `public/models/gt-seat.glb`；保留源文件用于编辑和复现。

四视图产生的前一个整车任务 3431294 出现重叠车体，未用于游戏。参考图是建模素材，不是游戏截图。

## Three.js 集成

- 动态轮组使用模型实际轮心、胎径和胎宽，转向围绕轮心，卡钳不随轮胎滚动。
- 车外可透过薄玻璃看到独立座舱、仪表台、门板与两张真实 Lux3D 座椅。座椅运行资产为 409,072 字节、8,190 三角形、一个 primitive、两张 1K 纹理；玩家外部座舱合计 19,452 三角形、6 次绘制。
- 驾驶视角使用独立细节层，引擎盖来自同一实际车身几何；换色和雨天清漆变化与车外一致。切换回车外时恢复玻璃原始的 `depthWrite:false`，避免透明窗挡住内饰。
- Paint、玻璃及金属反射采集当前道路、山体、建筑与天空。每帧采集一个立方体面，六面完成后才更新 PMREM；驾驶视角暂停采集并保留已完成的反射。
- 高档桌面反射 256，移动车辆最短更新间隔 1.6 秒；平衡桌面 128 / 3.2 秒；高档触屏 128 / 4 秒。静止时最短 8 秒，低档及触屏平衡默认关闭。关闭后恢复环境 HDRI。
- 反射采集排除本车与雨滴粒子，临时关闭主相机专用级联阴影接收，采集结束恢复。双缓冲保留最后完整反射，捕获或过滤失败会在冷却后重试，不中止驾驶循环。

## 最终资产与几何处理

最终整车 GLB 为 2,787,508 字节、73,914 三角形、48 primitives、10 材质、两张 2K 纹理，SHA256 为 `297340e14f29405e049ad0d2b71d0c268360be93c6d3bb7c8f606fc55dc2b7b1`。`lux-car-build.json` 的字节数和三角数与实际文件独立解析结果一致；`dist/models/` 中的整车与座椅和 public 源文件哈希一致。

实际保留 Lux 生成的下车身，经过焊接、12 mm 体素实体修复、有限幅度平滑和精确轮洞、灯腔裁切。原生成上舱存在自交和重叠内皮，不能直接作为可透视玻璃使用，因此在 Blender 手工重建共享边界的 Hermite 车顶/前后窗、Coons 侧窗与 A/C 柱、腰线过渡、低后甲板和双后视镜。这些修复部分不是原始 Lux 网格。旧的按三角质心筛删算法因实拍出现碎面被弃用。

前后 VZ-0606 均有实际牌底、蓝色条带、字母数字几何和安装螺钉。引擎盖最高点为 0.9066 m，V8 缩放后为 0.9338 m，低于固定 1.03 m 眼位；驾驶舱前方增加与仪表台连接的封闭斜面，防止路面从引擎盖下方透出。车外最低环绕距离为 3.4 m，可近看细节。

## 功能与画面检查

在独立 Chrome / Playwright 中检查最终模型：

- 1440×960 晴天与黄昏：实际拍摄前、后、侧、近看前脸和驾驶舱；前后牌文字均为 VZ-0606，双镜恢复，驾驶视野不再被高引擎盖挡住。
- 换色顺序 GT 橙、轻量银、V8 金、GT 青绿、GT 橙；车身与独立驾驶视角引擎盖颜色始终一致，重复回到 GT 后材质资源稳定。
- 夜晚及暴雨无页面或控制台 error。最终干燥 roughness 为 0.29 / clearcoatRoughness 0.15；暴雨湿度 0.9955 时约 0.19045 / 0.07534，车身和引擎盖一致。制动时 Tail emissiveIntensity 为 4.2。
- 切入驾驶视角时外部座舱隐藏、四窗 colorWrite/depthWrite 均关闭；切回车外恢复座舱和玻璃 colorWrite，同时保持玻璃 depthWrite=false。
- 390×844 和 844×390 Chrome 触屏模拟，设备 DPR 2.625，平衡档实际 DPR 1、2x MSAA、3×768 阴影、反射采集关闭。双指同时持方向与油门、单独松方向保持油门、全部松开清空输入均通过；触控换视角、旋转暂停和恢复正常，两种尺寸均无横向溢出。未使用实体手机验证。

截图 `output/playwright/lux-gt-hero-{front,rear,side,nose,cabin}.jpg` 是最终游戏黄昏实拍；`lux-gt-final-*` 保存晴天、天气与触控复测。素材参考图与中间 review 图不作为最终游戏效果的证据。

## 帧时间与质量切换

本机独立 Chrome，在 1280×800、DPR 1、多车发车区域 s=45，每档采样 240 个 requestAnimationFrame 间隔；包含暖机后一次完整反射更新。下表是短时浏览器回调间隔，不等同于 GPU 单帧耗时，也不是所有设备的帧率保证。

| 切换顺序 | 中位数 ms | P95 ms | P99 ms | 最大绘制调用 | 纹理资源 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 高 | 17.9 | 19.6 | 20.4 | 874 | 41 |
| 平衡 | 17.7 | 19.0 | 19.7 | 811 | 41 |
| 低 | 17.7 | 18.4 | 18.7 | 238 | 32 |
| 恢复平衡 | 17.7 | 19.5 | 20.3 | 579 | 41 |

各段对手持续行驶，绘制调用不是严格同步的性能比较。切低档后反射和阴影资源释放，恢复平衡后重新建立，反射完整更新计数继续增长；本轮无页面或控制台 error。

# 车辆操控验证

验证日期：2026-09-19。当前车型为 Aston Martin DB12、Ferrari GTC4Lusso、Ferrari 812 Competizione。以下是本游戏模型的测量，不是现实车辆标定。此前旧车型表格已由本次实际运行结果替换。

## 确认并修复的问题

1. 倒车速度约 6 m/s（22 km/h）后，原来的前轮动力学仍按前进方向计算转角引起的侧向力，而停车运动学使用带符号速度，两者混合后发生抵消或方向翻转。关闭辅助时可向错误方向回转，开启辅助时会失去转向响应。修复仅给前轮转角贡献加入行进方向，保留侧滑阻尼和现有正向驾驶计算。
2. 输入层用转角与横摆方向相反判定反打，未考虑倒车本来就会产生相反横摆，因而错误放大普通倒车转角。判定现在结合行进方向。

没有提高发动机功率、制动力或抓地力，也没有引入自动沿赛道转向。第一轮 TypeSafe 用于离线复核；第二轮新增独立浏览器实操工具，由 TypeSafe 选择转向并执行真实按键。模型不进入正式游戏控制循环，API 密钥只在后台测试进程读取。

## 当前三车基准

固定步长 1/120 s，初始默认轮胎温度，稳定辅助开启。0–100 km/h 全油门不加氮气；100–0 km/h 制动截止为速度低于 0.1 m/s。湿路 wet=0.9。

| 车型 | 0–100 km/h | 干地刹停距离 | 湿地刹停距离 |
| --- | ---: | ---: | ---: |
| ASTON MARTIN DB12 | 2.95 s | 36.28 m | 43.63 m |
| FERRARI GTC4LUSSO | 3.17 s | 36.62 m | 44.01 m |
| FERRARI 812 COMPETIZIONE | 2.91 s | 35.30 m | 42.51 m |

修复前后，上述加速/制动和 60/100/160/220 km/h 干湿地轻点修线数据完全一致。30 组倒车观测中，原有 6 组出现错误横摆方向；修复后为零。新增测试覆盖三车、五档倒车速度、两侧转向、干湿地与辅助开关，共 120 组组合，并检查转向响应未被辅助抵消。

独立探针在 -9 m/s、正转向 0.3、辅助开启时，三车横摆速度分别为 -0.29341 / -0.27602 / -0.29575 rad/s，接近同轮角停车模型参考。3–9 m/s、辅助开关均无方向翻转；松舵收敛，反打只过零一次。此探针固定纵向速度并移除道路碰撞影响，不能把它的结果当作真实道路轨迹。

## TypeSafe 实际调用

使用本机已配置的 TYPESAFE_API_KEY，按官方 HTTP v1 systemone 接口真实调用两次，model=jev-latest，服务返回 jev-1.13.0。每次批量 9 个 Choice，分别评价三款车的倒车、制动和轻点修线。

修复前，三车倒车均被标为 defect，confidence 分别为 0.36 / 0.81 / 0.76；低置信度结果不能单独支持修改，缺陷由独立模型运行和失败回归测试证实。修复后均为 consistent，confidence 为 0.94 / 0.97 / 0.96。其他六项均为 consistent。AI 判定不等于测试通过或现实安全认证。

两次返回用量合计 input_tokens=34140、output_tokens=795。未推算费用。请求、原始响应、耗时和测量 JSON 保存于 output/typesafe-handling/，不包含 API 密钥。

## TypeSafe 浏览器实际操作（2026-09-19，第二轮）

本轮重点是让模型操作，而非再判断离线数值。工具为 `tools/typesafe-live-driver.py`（仅监听 127.0.0.1 的请求桥接）和 `tools/typesafe-live-browser.js`（Playwright CLI 真实按键）。使用现有开发测试接口只设置各场景初始位置/速度，随后不直接修改车辆状态。测试画质 balanced、晴天、辅助开启，三车型分别实际运行；油门由测试执行器控制速度，方向由 TypeSafe 选择。未新增游戏转向参数改动。

### 实际请求及方法边界

- 共 31 次 TypeSafe HTTP 请求，服务返回模型 jev-1.13.0。30 次成功，一次 8.017 秒超时；成功延迟为 0.904–3.322 秒，中位 1.526 秒。返回用量合计 43,591 输入 tokens、2,293 输出 tokens；超时请求没有返回用量，未计入合计，不推算费用。
- 首轮是游戏持续运行的闭环：三次请求中，一条超过 3 秒被丢弃，一条实际执行，一条超时后中止。它没有完成蛇形目标，不能算连续实时驾驶通过。
- 后续 28 次是分步实操：读取状态后暂停推理，恢复游戏、真实按键，再松舵约 650 毫秒；不是高速连续控制测试。记录包含实际模拟时间与按下/释放时间，避免将接口耗时当成转向响应时间。
- 立即反打场景由 TypeSafe 选择首个方向，执行器再按预定协议施加反方向 200 毫秒。整段反打过程中没有暂停；不能把第二个方向也称为模型决策。

### 实际结果，不将模型失败计为车辆通过

| 场景 | 结果及解释 |
| --- | --- |
| DB12，30 km/h，8 次修线 | 全部真实方向输入、轮角、横摆对应；零碰撞。末尾距道路中心约 1.92 m，模型未精确跟随目标。 |
| GTC4Lusso，30 km/h，8 次修线 | 全部真实方向响应正确；零碰撞。末尾距中心约 0.23 m。 |
| 812，45 km/h，7 次弯道修线 | 模型一直选 60 ms 短脉冲，随后松舵 650 ms，转向总量不足，越过测试范围。首次越界前零碰撞；最后一次碰撞发生在旧执行器未立即暂停的尾段，不用于判断车辆物理。 |
| DB12，立即反打 | 首次轮角 +0.234 rad、横摆 +0.491 rad/s，反向后轮角 −0.358 rad、横摆 −0.552 rad/s；换向正确、无碰撞。 |
| DB12，倒车选择 | 四次均选 neutral，没有实际方向动作，且初版测试控速方式使倒车速度波动；本轮倒车方向未得到验证，不能记为通过。此前单独倒车测试见上文。 |

前三个分步场景共 23 个转向脉冲，均有正确的原始输入、实际轮角和横摆方向；在安全范围内完整松舵段，实际模拟时间 0.650–0.667 秒，残余轮角最大约 1.6×10⁻⁶ rad、横摆约 2.8×10⁻⁵ rad/s。暂停会重置输入记忆，但这些松舵段已超过 0.6 秒记忆期限，因此没有用暂停掩盖松舵响应。轨迹不能仅凭横向位置误差判为物理故障。

812 首次越界前约 5.042 秒，道路累计方向变化约 0.2486 rad，车辆实际转动约 0.0606 rad，仅达约 24.4%；差值与实测相对道路车头误差吻合。同一路段另做七次固定 A 120 ms + 650 ms 松舵对照，不请求 TypeSafe：6.375 秒后 d=−3.342 m、零碰撞，转向响应增强但仍未精确居中。这支持操作量不足的解释，不代表该固定按键序列是合格自动驾驶策略。

### 执行器修正与保存

已将测试范围触发后的处理改为立即释放所有按键并暂停。单独停止验证从初始取样到末状态推进约 58.3 毫秒模拟时间（约 96.1 毫秒墙钟），已暂停、零碰撞、所有输入清零；执行脚本另等待 400 毫秒并通过位置不变断言。初版失败记录完整保留，不覆盖。倒车测试工具改为持续按住 S，避免频繁松按触发制动/倒车切换；这项工具调整尚未用新的 TypeSafe 倒车方向动作复验。

原始请求/响应、按键事件、轨迹、截图、失败记录与固定按键对照在 `output/playwright/typesafe-live/`。通过 `python tools/typesafe-live-report.py` 可重新生成本地报告。临时 TypeSafe 桥接已关闭；前端无新增 AI 依赖。实体手机、雨天及高速连续 AI 控制不在本轮结论内。既有倒车修复仍为本地版本，未发布。


## 根据实操结果实施优化（2026-09-19）

用户要求将测试结果落实为具体优化。本轮修改 `src/driving-input.js`、`src/physics.js`，不改变动力、轮胎抓地力或渲染资源。

- 只加快中低速轻点的起始段，随输入建立及速度增加平滑退出。90 km/h 以上输入增益为零，保留原有 `<0.08` 单步输入变化检查、反打速度与轮角上限。
- 已主动接合倒车后，松 S 滑行仍保留倒车选择，再按 S 直接恢复动力。修复前约 0.692 秒重接等待使三车从 −14.2 km/h 减至 −0.8～−1.3 km/h；修复后首个积分步可恢复，0.4 秒后约 −16.4 km/h。
- 首次倒车计时限定在近停区间，防止意外快速后溜时尚未减速就再次反向加速。W 清除倒车记忆，W+S 优先制动；自然滑停的当帧也清除记忆，立即重按 S 仍保留首次等待。

最终 144 组前后对照覆盖三车、8 个速度、干湿地及3种按键时长。30–60 km/h 的 66.7 ms 短按，1秒后的车头转角增加 14.7–19.9%；100/160/220 km/h 的54组全部逐项一致。所有对照零碰撞，不据此推断无限场景都无碰撞。

新增15个倒车踏板回归，包含重新接合、刚滑停当帧、前进选择、双踏板及意外后溜。215项完整测试通过，生产构建成功；保留既有较大打包块提示。三车真实键盘再按S、轻点转向及手机触控取消通过；手机布局模拟约60FPS、p95约17ms、5秒中无超过50ms帧，无脚本错误。最后一项停车当帧修正由回归测试验证；浏览器实操记录验证移动中的重新接合与最终转向曲线。
